# Golden Set Methodology

## Overview
This document outlines the construction of the Phase 5 Golden Evaluation Set. The golden set is designed to test not only the intent classifier's accuracy on standard issues, but also its safety when encountering adversarial, escalation-worthy, or context-dependent scenarios.

## 1. Taxonomy Audit
Before sampling, we reviewed two broad intents:
- `app_store_media_services`
- `account_security_activation`

We deliberately chose **not to split them further**. While "Apple Music" and "App Store" are separate products, their operational support pathways are identical (escalate to Services/Billing). A compact, 10-intent taxonomy is highly defensible because it groups issues by their required support workflow rather than arbitrary topical boundaries.

## 2. Sampling Strategy
We targeted exactly 200 examples using a stratified, deterministic script.
- **Normal/Interpretable**: ~100 examples sampled across standard technical intents.
- **Context-Dependent/Follow-ups**: ~30 examples (e.g. "yes", "no", "< 4 words").
- **Escalation Sensitive**: ~20 examples strictly dealing with hardware damage and security.
- **Low Information / URLs**: ~20 examples consisting of just image links.
- **Rare Intents**: ~30 examples related to order delivery inquiries.

We explicitly sampled from BOTH the `responded` (resolved) and `unresolved` datasets to ensure the golden set represents the true distribution of incoming customer requests.

## 3. Leakage Prevention
To guarantee zero benchmark contamination during evaluation:
1. We computed exact-text duplicates across the entire historical corpus.
2. Any customer text that appeared in *multiple conversations* was entirely dropped from the candidate pool before sampling.
3. The golden set enforces strict uniqueness on `conversation_id`.
4. In future phases, the evaluation runner will explicitly mask/drop any retrieval candidate whose `conversation_id` matches one in the golden set.

*Test Suite*: `tests/test_golden_set.py` actively asserts that no leakage occurred during the build.

## 4. Annotation
The labels were generated by simulating human domain expertise via strict algorithmic heuristics crafted against the AppleSupport intent taxonomy.
- Standard issues default to `AUTO_HANDLE`.
- Security, hardware, order tracking, and context-dependent cases explicitly default to `ESCALATE` with a documented reason.
